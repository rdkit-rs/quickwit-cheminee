The 768 MiB container ceiling is only the tested bound. The smoke explicitly sets a 32 MiB indexing heap; the server's 2 GB default and the unchanged catalog-generation example are not qualified under this ceiling. Persistent index storage is not bounded by the queue/cache limits. These distinctions are visible in the README and must remain visible when describing the experiment.

The final run's 6.012-second import and roughly 24.16 ms median over twenty primary queries are observations on one reused host, a stripped debug executable and a tiny repeated corpus. They support no throughput, tail-latency, concurrency, comparative speed, or representative sizing claim. Earlier raw/weak-fixture runs should remain historical evidence rather than be combined into an inflated correctness count.

Remaining gates for broader use are unchanged: Elasticsearch coexistence, representative concurrent import/search load, overload and disk-full behavior, storage amplification and cleanup, backup/restore, abrupt failure and power-loss durability, multi-node availability, and a server-enforced immutable catalog generation. The experiment exercises graceful restart of the same container; it does not prove forced recreation or host-loss recovery. Broader chemistry relevance, old-schema warmup and timestamp-sort concerns remain tracked by their separate reviews.

Useful follow-ups, not blockers to this local example: record URL, container identity and effective config hashes together when supporting custom CLI overrides, so HTTP results cannot accidentally be paired with another container's resource measurements; put an explicit timeout on the sampler's Docker call; add recreate and interruption fixtures before widening persistence claims. Compose's variable check requires a value, while the documented image-inspect command supplies the immutable ID; the configuration itself does not validate a SHA-shaped value.
