Independent next-step design review, 2026-10-16. **Use a bounded, request-scoped membership rewrite after eager validation to fix count-only OR with a guaranteed MatchAll alternative.** Do not change global score-preserving Boolean simplification, add an unconditional verifier, or catch chemistry/storage failures. This recommendation is based on source inspection; it is not a claim that the next fix has been implemented or tested.

The four observation-only cases in `quickwit/tantivy-rdkit/poc/relevance.py` currently issue strict size-0 OR queries with MatchAll plus stored-corrupt Tanimoto/containment, in both orders. Retained `contract1-final-relevance.json` records HTTP 500 for all four. Their fixture has three live documents across two splits; `composable.py:250` deliberately stores one malformed fingerprint. Under the accepted relevance contract, each OR's membership is all three documents independently of the chemistry result, so the correct exact count is 3. Invalid syntax, options, chemical inputs and current declarations must still fail eagerly.

The architecture explains the current behavior:

- Root `validate_request_and_build_metadata` (`quickwit-search/src/root.rs:184`) parses and builds the original query against every current index declaration at lines 243–259. It then invokes `narrow_chemistry_candidates` around line 279 before the resolved AST is serialized for split planning and execution. This is the safe integration point.
- `TantivyBoolQuery::simplify` in `quickwit-query/src/query_ast/tantivy_query_ast.rs` preserves should clauses because they may affect scores. Globally collapsing OR(MatchAll, chemistry) there would break ranked requests.
- Pinned Tantivy `boolean_weight.rs:226` constructs each child scorer before reducing constant scorers. Disabling scores alone therefore does not prevent chemistry verification failures.
- Leaf `doc_mapper.query` prepares warmup information before execution. `QueryFastFields` in `quickwit-doc-mapper/src/query_builder.rs` walks the AST, including chemistry fields. A scorer-only shortcut would still permit irrelevant column warmup/I/O. The same reduced AST must reach planning, warmup and cache preparation.

Implement the first slice as follows:

1. Leave the complete original-query validation loop untouched. After it succeeds for every current index, apply a separately named count-membership transformer before the existing candidate planner. Gate it to plain exact count requests: `max_hits == 0`, CountAll, no aggregation, snippets, scroll or search-after. Requiring zero offset is a reasonable first-slice restriction. Validate any supplied sort fields as today. Requests returning hits retain their original scoring semantics; dynamically disabled top-K collection is not a new eligibility signal for this patch.
2. At a Bool node, count **literal** MatchAll children of `should`. If at least one exists and that count satisfies `minimum_should_match` (an unspecified minimum is at most one), the entire should collection is irrelevant to membership. Clear only `should`, set `minimum_should_match = Some(0)`, and retain every `must`, `filter` and `must_not` clause. If no other clauses remain, return MatchAll. The explicit zero prevents an old positive minimum from turning an emptied should collection into MatchNone. Keep insufficient/unknown cases unchanged. Recognizing literal constants avoids inferring tautologies from data, index statistics or failed evaluation.
3. Recursion through ordinary Boolean/wrapper nodes is safe in this count-only mode, but keep chemistry nodes and their explicit candidate subtrees opaque for the first slice. Never return transformer `None` to erase a required node; replace only a proved equivalent subtree. This transform only removes nodes and adds no copied candidate expressions or deeper wrappers.
4. Serialize and execute the resulting AST through the existing planning path. Do not retain a hidden original AST solely for runtime verification, and do not derive warmup requirements from branches already proved irrelevant. Keep strict failure handling for all remaining required data and count work. This bypasses unnecessary work by proof; no exception is converted to a successful result.

A pure OR becomes the existing MatchAll count path, which may answer from published split counts. That is a count result, not a claim that the skipped chemistry bytes are healthy or that every split was opened. Preserve ordinary metastore, count and relevant leaf failures. The gate must exclude scroll because a rewritten query stored for later hit retrieval could lose scoring semantics.

Required acceptance tests:

| Domain | Expected outcome |
| --- | --- |
| Existing four observations | Both clause orders, Tanimoto and containment, strict size 0: HTTP 200, exact total 3, no hits, no failed splits or timeout/early termination. Change the probe helper to accept an explicit expected total; it currently assumes every successful case means zero. |
| Eager validation | Repeat the existing invalid syntax/option/spec/fingerprint/SMILES/candidate-field/current-declaration cases under OR(MatchAll, invalid), both orders: the same HTTP 400 and diagnostic cause remain. Validation must precede reduction, including on an empty catalog or when another Boolean branch proves emptiness where that existing contract applies. |
| Remaining membership dependence | OR(MatchNone, corrupt), OR(selective ordinary term, corrupt) covering documents outside that term, NOT(corrupt), and MatchAll+corrupt with MSM 2 remain failures with the stored-data cause. Optional-looking clauses must not be discarded when their minimum still requires them. |
| Preserved surrounding constraints | A qualifying OR nested under ordinary must/filter retains those predicates and their exact count; under a pure must_not it yields exact zero. A corrupt required/excluding chemistry sibling remains fatal. Do not claim arbitrary Boolean relevance from these bounded identities. |
| Constant threshold arithmetic | One MatchAll with MSM 1 and unspecified minimum; two MatchAll clauses with MSM 2; insufficient constants; impossible MSM with invalid input. Preserve existing impossible-MSM eager-validation regressions and negative/minimum parsing behavior. |
| Ranked and excluded modes | Size > 0 with `_score` ordering still evaluates rank-relevant chemistry and fails on corruption. Run count then ranked and ranked then count to detect cache contamination. Aggregation, scroll and search-after requests must not enter this new transform. |
| Warmup and I/O | Assert the executed count AST and warmup requirements omit the eliminated chemistry field. A fail-on-read/counting test double should show that a pruned chemistry branch is never evaluated, while required ordinary postings/count I/O failure still propagates. Do not make a missing/corrupt entire split silently successful when its contents are required to determine a filtered count. |
| Truth and storage controls | Compare healthy-fixture counts before/after reduction, include deleted/empty domains where supported, and test a graph-corruption fixture separately before extending the native HTTP claim to molecular graph verification. |

The narrow rule does not solve per-document OR short-circuiting, arbitrary tautologies, optional score clauses in all contexts, rank-independent hits, score-dependent aggregations, or every nested NOT/MSM error domain. Those require a wider relevance plan and additional proof. It also does not justify a blanket success result for failed leaves. The benefit of this slice is that the four known count-only failures can be corrected with a small explicit proof at an existing validated planning boundary, without changing storage error handling or the chemistry scorers.
