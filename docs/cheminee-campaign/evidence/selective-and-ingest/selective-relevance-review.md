1. `quickwit/quickwit-query/src/query_ast/chemistry_candidates.rs`: only direct required `must`/`filter` terms, term sets, ranges, existence checks, and `match_none` become guards. Stack truncation prevents a local guard escaping into an OR sibling. Inherited necessary guards may safely enter optional and negative descendants: outside a necessary ancestor guard those descendants cannot affect the enclosing result. Optional/negative operands themselves never become positive guards. The original outer clauses remain, so their scores and Boolean requirements remain intact. Wrapping the original candidate AST preserves an implicit should-only minimum. The correct equivalence oracle is `P AND C(D)` versus `P AND C(D AND P)`, retaining `P` on both sides.

2. `quickwit/quickwit-search/src/root.rs::validate_request_and_build_metadata`: the original resolved query is built against every current index schema before narrowing. This preserves eager syntax, chemistry input, options, and declared-schema failures, including dead Boolean branches. Planning precedes shared metadata, split selection, serialization, and cache keys. The 4,096-copy/1 MiB limits fail the request rather than silently changing execution strategy. The post-expansion deserialize check reserves the possible leaf Boolean and cache wrappers and prevents a valid input becoming an unreadable leaf request. These limits are safety bounds, not demonstrated workload sizing.

3. `quickwit/quickwit-search/src/root.rs::ExtractTimestampRange`, `lib.rs::list_relevant_splits`, and `leaf.rs::remove_redundant_timestamp_range`: floor lower bounds and ceil upper bounds conservatively preserve subsecond membership; Euclidean arithmetic handles negative epochs. Widening old nonpositive split lower bounds and metastore pruning accommodates metadata written with truncation toward zero. Checked conversion, or omitting an unrepresentable coarse bound, leaves exact AST comparisons authoritative at i64 nanosecond extremes. The new `leaf.rs::timestamp_literal` keeps a numeric literal only when reparsing produces the exact same timestamp; otherwise RFC3339 avoids both rejected negative numbers and mis-inferred near-epoch units. All representable i64 nanosecond dates fit RFC3339's year range. Explicit chemistry candidate timestamp boundaries remain inside chemistry.

For the old-schema gate, the narrow coordinated implementation is:

- Keep `BuildTantivyAstContext.schema` as the physical split schema for ordinary/candidate query compilation and field IDs. Add a separate current chemistry schema reference, supplied by `DocMapper::query` from `self.schema`. Only two context construction sites currently exist: the mapper and `for_test`.
- Pass that logical chemistry schema to the three chemistry constructors. Preserve strict constructors, `validate_graph_contract`, native graph input validation, and the existing refusal to swallow `InvalidChemistry` under `with_validation=false`. Root already builds against the current schema and forwards the current mapper to leaves (`root.rs::validate_request_and_build_metadata`; `leaf.rs::multi_index_leaf_search`).
- Reuse physical contract validators in the scorers after candidate scorer construction, skipping deleted candidates, and finding the first live candidate. `SegmentReader::schema()` is available. Fingerprint verification must retain bytes/fast checks. Graph verification must retain requested fingerprint presence/type/fast and prepared text/stored/fast/raw checks; today `GraphQuery` drops the fingerprint specification after construction, so retain the specification or required fingerprint name for this check. A string column alone cannot prove raw normalization. Keep graph matcher setup before the empty-domain return.
- Split chemistry warmup collection from ordinary range warmups in `quickwit-doc-mapper/src/query_builder.rs::QueryFastFields`. Warm chemistry only for an exact compatible physical field; do not resolve absent chemistry names through `_dynamic`, and do not globally suppress warmup errors. Tantivy fast-field name resolution can fail on non-fast fields before the scorer. Live-candidate physical validation remains responsible for the invalid chemistry contract.
- Regress missing fields, wrong types, non-fast fields, nonraw prepared columns, deleted-only candidates, nested candidate errors, and mismatched field ordinals between current/old schemas. This prevents accidentally compiling ordinary candidates against current-schema field IDs.

One separate pre-existing concern remains source-inferred, not HTTP reproduced: `leaf.rs::CanSplitDoBetter::record_new_worst_hit` rounds a descending timestamp cutoff upward, while `can_be_better` compares that cutoff with a split maximum stored by truncation. A cutoff at +1.5 seconds becomes 2, but a split containing a better +1.7-second hit has metadata end 1 and can be discarded. Add a multi-split subsecond timestamp-sort regression before claiming general timestamp-sort exactness. The SDK's score/record-ID sort does not use this timestamp-specific optimization.
